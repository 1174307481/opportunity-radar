## 二、最重要的发现：评分尺度 bug（P0，产品审查抓出）

**现象**：60 条真实采集数据分档分布 58 归档 / 2 今天 / 0 本周 / 0 观察——中间档数学上不存在。

**根因**：L2 提示词写「四维打分（需求真实性40/行动可行性30/独特性15/时效性15）」，模型把这当成了**各维满分**（实测四维上限 30/20/12/13）；`computeTotalScore` 又按 40/30/15/15 权重**二次加权** → 总分理论上限 ≈22，🟡本周档（40-69）永远不可达，三档制退化成两档。

**修复**：prompt 改为「每维 0-100 分」+ 给出各维评分锚点（有预算+时间窗=85+；TG 匿名中介≤35 等）；全量 60 条重打分。

**教训**：冒烟测试只验了「单条质量」，没验「分布健康度」。**分档分布本身就是最有用的监控指标**。

### 6.2 AI 评判质量盲测（17 样本，含全部 today/week + 随机归档/噪声）

**评分：L1 5.0/10 · L2 6.0/10 · 综合 5.5/10**（冒烟基线 8.5，降 3 分——冒烟样本全是真需求，没测到「无需求方公开信息」这片生产语料主区）。

强项（保持）：**证据诚实度极高**——65 个非 null 依据 58 个原位命中、0 条伪造原句；null 克诚；红队具体（点名的都是真竞品）；13/13 第一步含「不接免费试稿」红线 + 可直接发送的话术。

三大系统性偏差（全部定位到 prompt 原句）：

| # | 偏差 | 根因 | 修复 |
| --- | --- | --- | --- |
| 1 | **打分压缩**：四维无一 ≥70、总分天花板 52，`score≥70→today` 成死代码；41/42/42/42 无区分度 | 锚点只剩高低两档、中段全丢；「证据不足敢打低分」把缺证据当机会差 | 锚点改 5 档刻度 + 「判据是机会对主人值多少，不是原文证明了多少」+ 置信度分两段写 + 校准自检 |
| 2 | **独特性口径错**：接单帖「公开可见」被扣分（真实剪辑单 20 分）；公益帖却拿全库最高 55；时效性把常青需求判死（全库 max 65） | 接单类按「竞争可见度」打独特性=口径错误（redteam 03 早已判过死刑）；无「常青不扣分」规则 | 独特性按 category 切口径（接单问议价权、信息差问别人知不知道）；时效性补常青档 60~75 |
| 3 | **日期幻觉**：prompt 无今天日期，模型自造「2026-05-07」，7/37 条正常日期被判「未来数据异常」写进三证甚至红队 | 两级 system prompt 均未注入日期 | 注入今天日期 + 「晚于今天才可称未来日期」硬规则 |

次级缺陷同批修：verdict 无判据无「做」档（37 条 0 次出现）→ 按总分+红队可验证性出档；has_budget 假阳性（平台测试金额/假设性付费）→ 三条件规则；L1 噪声定义缺「无需求方」类 → 补 GitHub 元数据/教程/自荐等 + 「无法回答谁在付钱就是噪声」；降权只写 reason 机器读不到 → schema 化 `downweight`+`risk_flags`；快通道可被软技能授予 coreHit → 软 token 不算 coreHit。

**快通道裁决：保留**。它是当前唯一通向首页的通道，且救回了全库最佳机会（15000 元托管单，skillMatch=30 本应被 <40 规则误杀）。改造：降权否决 + 徽章改「⚡ 接单·待验真」+ 首页排序降到分数通道之后。

## 七、持续优化机制（固定节奏）

1. **每周复审分布健康度**：分档分布（today/week/archived 比例）、L2 有效率（非归档/进 L2）、每源 A+B 级产出。分布塌缩（如再度全挤在 20-35）即触发 prompt 校准。
2. **M4 校准闸（数据满 7 天）**：HN 重调后 A 级产出是否 >0（否则杀）；电鸭扩窗后今日产出增量；快通道否决率（downweight 拦截了多少接单）。
3. **评分锚点回看**：重打分后若 max 仍 <60 或「做」档仍为 0，回到 §6.2 表逐档核对锚点。
4. 闲鱼价值全部走人工快录（合规红线不爬）；批量粘贴已支持，后续观察使用率决定是否做闲鱼专用模板按钮。
