> 2026-09-11。由 6 份专项研究交叉综合而成（见 `research/01~06`），取代 product-design-v1.md 中与本文冲突的章节。

## 1. 产品定义 V2

### 1.1 一句话

> **不是信息产品，是行动工具：把互联网信号变成「你今天该做的下一件事」。**

### 1.2 护城河公式（竞品研究结论）

```text
个人技能画像作为核心过滤器 × 行动工件作为交付单元
```

- Trends.vc 有趋势无匹配，Follow 有摘要无行动，生财有术有项目无个性化，企查查有监控无机会——这个乘积位置无人占据，且 LLM+代码即可实现，单人可做
- 已证伪的两条路（绝不走）：AI 摘要聚合（所有 RSS+AI 工具留存曲线同形：注册→订源→堆积→不再打开）；纯趋势/信息差报告（被收购即消亡，无个性化则不复购）

### 1.3 系统的 KPI（不是信息指标）

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| 本周行动数（联系/挂单/交付） | 唯一 KPI | 系统的全部存在意义 |
| 回复率 | 领先指标 | 比成交更早给正反馈 |
| 成交金额 | 滞后指标 | 配合每周归因结论（「这单来自 9/3 你录入的 JD」） |

### 1.4 唯一必保功能（生存审查裁决）

> **快速录入 → 5 分钟内得到「该不该做 + 第一步做什么」。**

采集只是输入放大器，分析引擎才是产品本体。「粘贴一条信息」30 秒零维护永不失效；采集管道的维护正是第三周死亡的标准路径。自动采集是放大器，必须做，但永远排在核心闭环之后。

## 2. 设计原则（修订版）

PRD 六原则全部保留，叠加本轮新增七条：

7. **过滤先于排序。** 每天看 5~20 条的系统，核心决策是「今天看不看」，不是「78 还是 76」。当日合格机会不足时，首页直接显示「今天没有值得看的机会」——**宁可空手，绝不凑数**
8. **信号类型优先于数字分。** 接单类只要需求方真实 + 有预算，直接进今日必看，跳过一切加权平均
9. **每个结论必须带证据和理由。** 说不出理由的分数自动降档；红队审查必须引用原文具体数字/主体
10. **没有行动建议的机会不允许进首页。** 分析只服务行动，交付单元是「今天的一个动作 + 可复制的物料」
11. **人工录入是一等公民，不是妥协。** BOSS/闲鱼等禁爬平台走「刷到就粘贴」，30 秒
12. **功能靠产出解锁。** 简报/推送/学习等次级功能，锁在「系统连续 7 天有产出」的闸门后面
13. **信息源接入标准 = 能否产出「谁在花钱 + 需要什么技能」。** 纯新闻源免费也不接

## 4. 分析流水线 V2（取代 V1 §6 的调用分层定义）

模型仍是 DeepSeek 双档（L1=对话档，L2=推理档），但分工重定义——**L1 从「筛查」升级为「分类路由」，L2 从「打分」升级为「行动工件生成」**：

```text
Item 入库（采集或人工粘贴）
  ↓
L1 分类路由（对话档，全量）
  ├─ 噪音 → ⚪ 归档（信息库可搜，不产生机会）
  ├─ 接单 + 需求方真实 + 有预算 → 🔴 快通道：直接进「今天看」
  └─ 其余有信号 → 进 L2
  ↓
L2 行动分析（推理档）
  ├─ 真伪三证：资金证据/身份证据/时间证据（三缺一 → 降级「观察」，禁止推进）
  ├─ 四维打分（每维必须带一行引用原文的理由，说不出 → 该维减半）
  ├─ 红队审查 devil_advocate（必须引用原文具体数字/主体，否则视为套话重跑一次）
  ├─ 强制输出 missing_resource（这条机会需要而你当前没有的资源；填不出 = 套话）
  ├─ Skill Match（代码计算）：<40 → ⚪ 归档；40~60 → 最高🟡；≥60 → 可进🔴
  ├─ 召回 playbook（按机会类型+标签取 top 2~3 注入上下文）
  └─ 生成行动工件包（见 §6）
```

### 4.1 四维评分（取代 V1 八维度）

| 维度 | 权重 | 口径要点 |
| --- | --- | --- |
| 需求真实性 | 40 | 需求方+预算+时间窗=90+；有需求方无预算=50~70；仅推测≤40。领域放大器 +0~8 |
| 行动可行性 | 30 | 技配≥60% + 交付≤1月 + 利润为正=80+，任一不满足逐降。含时薪反算（报价÷工时<底线时薪 → 直接劝退） |
| 独特性 | 15 | 国内无同类=80+；有竞品可差异化=50~70。领域放大器 +0~6 |
| 时效性 | 15 | 有 deadline=90+；**常青内容=70（不被旧惩罚）**；过时≤30 |

**砍掉的理由（红队模拟实证）**：竞争程度（把真实接单压到成功故事之后）、信息新鲜度独立维度（埋掉常青路径）、利润空间（LLM 估不准，交给报价参考卡的三锚点法）、付费意愿（与需求真实性耦合）。

### 4.2 三档呈现（取代连续分数）

| 档 | 条件 | 展示位 |
| --- | --- | --- |
| 🔴 今天看 | 接单快通道 或 总分≥70（且技配≥60） | 首页，≤3 条 |
| 🟡 本周看 | 总分 40~69 | 机会列表，首页不展示 |
| ⚪ 归档 | <40 或 技配<40 或 噪音 | 仅搜索可见 |

用户操作改为**改档位**（「这条进今天看」比「78→85」诚实）；六类机会分类保留为**标签**（召回 playbook 用），不再承担评分职能——接单类独享快通道地位。

## 5. 行动工件体系（V2 的灵魂，新增章节）

决策链八环节，每个环节一个工件，分析的结果不是「一段分析」而是「一组物料」：

| 环节 | 工件 | 要点 |
| --- | --- | --- |
| 判真假 | **真伪三证卡** | 资金/身份/时间三证，三缺一降级「观察」 |
| 判能否做 | **能力缺口卡** | 重点列「你不会的 20%」+ 能否外包/AI 补/绕过 |
| 判值不值 | **时薪反算卡** | 报价÷工时 vs 底线时薪，低于即劝退 |
| 第一步 | **24h 验证清单** | 接单=发 3 条私信+平台挂服务看被动询单；信息差=3 个免费试点换案例；价差/资源差=直接挂单 ¥9.9~99 看转化；效率差=免费给 1 个商家做一单问复购；产品类=跳过（先有 3 个付费单才谈产品） |
| 联系 | **话术卡** | 身份背书→引用原话→给最小价值→问小问题；首次联系绝不报价；先给成品是最强开场 |
| 报价 | **报价参考卡** | 三锚点（平台成交价×1.3 / 挂单价×0.6 / JD 薪资反推×2.5~3）；样本<3 时切换区间报价法（三档让客户选）；低于底线时薪不报价 |
| 交付 | **MVP 方案卡 + 交付边界卡** | 第 1 周末必须有客户能点开的链接（假数据真流程）锁预期收定金；交付物清单+修改次数上限+验收标准+尾款节点 |
| 跟进 | **跟进节奏** | 3 天换渠道给新东西 / 7 天给价值不留台阶 / 14 天明确退出 / 21 天沉睡；提醒必须带已写好的新话术，复制即发 |

### 5.1 「今天做这一件事」

每天首页必须把 1 个机会变成 1 条指令。选法 = **分数 × 可执行性**（预算明确 + 联系方式可得 + 今天能发出第一条消息，三者齐备才当选）。

格式：`时间盒 + 动作动词 + 对象 + 渠道 + 数量 + 完成判定 + 复制即用物料`。
完成判定**只定义用户可控的行为**——「发出即完成，回复不是你能控制的」。
禁止输出「关注 AI 教育赛道机会」这类指令。

例：「今天 21:00 前，在 BOSS 找到该 JD 发布者，发 1 条私信（话术已生成）+ 加微信，不报价。判定：发出即完成。完成后推到『已联系』。」

### 5.2 行动账本（首页顶部，取代「今日发现 N 条」）

```text
本周行动  联系 7 · 挂单 2 · 交付 1      ← 唯一 KPI
有回音    3 条（回复率 43% ↑）
钱        在谈 ¥6000 · 已收 ¥1200 · 累计 ¥3.4k
距目标    本季度目标 0/1 · 已过 23 天    ← 建库第一天强制填写
```

加两条硬机制：
- **每周归因结论**：「这条 ¥6000 的单，来自 9/3 你录入的那条 JD」——全系统唯一能证明「它帮我赚到钱」的证据
- **沉默惩罚**：连续 3 天无行动 → 顶部变红：「你本周看了 47 条机会，发了 0 条消息。」

## 6. 状态机 V2（9 态 → 4 态 + 忽略族）

```text
新发现 → 研究中 → 已联系 → 成交
              └────────────→ 忽略（无价值/不适合我/已有人做/暂无需求）
```

- **「收藏」动作取消**：收藏 = 进入「研究中」（消灭零成本收藏夹坟场）
- 「有回复/报价/交付/复盘」等细粒度状态作为字段预留不进 UI
- 已联系 3 天无变更 → 自动生成带新话术的跟进提醒（放首页，不推送）

## 7. 首页 V2 与开箱体验

### 7.1 首页结构

```text
┌────────────────────────────────────┐
│ 行动账本（§5.2）+ 跟进提醒（如有）      │
├────────────────────────────────────┤
│ ⭐ 今天做这一件事（1 条，含复制即用物料）│
├────────────────────────────────────┤
│ 🔴 今天看（≤3 条：类型/分档/一句话理由/  │
│    该不该做+第一步；看完必须标记动作）    │
├────────────────────────────────────┤
│ 或：「今天没有值得看的机会」（宁空勿凑）  │
└────────────────────────────────────┘
```

页面从 7 个砍到 6 个：今日首页 / 机会列表 / 机会详情 / 信息库 / 快速录入 / 设置。**信息源管理后台砍掉**（配置文件 + 设置页只读列表）；周报砍掉。

### 7.2 第 1 天开箱

- 落地页只有粘贴框 +「30 秒，先丢一条进来」
- 预置 3 条示例机会（分档 91/78/55，覆盖接单/信息差/价格差），每条问「你会做吗？会/不会」——两次点击完成口味校准
- 预置源包 4 + 1 空格一键启用，**跳过也完全可用**
- 首次必填「本季度目标：我想通过它赚到 ____」

## 11. 冲突裁决记录（6 份研究间的不一致，本文如何裁）

1. **评分维度数**：生存审查砍到 3 维 vs 红队 4 维+闸门 → **采纳红队**（有 20 条模拟推演实证；生存审查砍的是「维度数量」，红队砍的是「维度参与方式」，闸门制吸收了两者）
2. **六类机会**：生存审查砍到 3 类 vs 信号地图/playbook 按六类运转 → **保留六类但降级为标签**（只用于召回 playbook，不参与评分；接单独享快通道）
3. **技配阈值**：红队 <40 归档 vs 竞品研究 <60 不进机会中心 → **取两者**：<40 归档；40~60 封顶🟡；≥60 才有资格🔴
4. **推送**：PRD 要求 vs 生存审查砍掉 → **砍**。问题不是「不知道」是「不行动」；M4 后若连续使用再议
5. **周报**：PRD 要求 vs 生存审查砍掉 → **砍**。7 天产出闸门之后再说
6. **源数量**：信号地图推荐 5 渠道 vs 生存审查硬上限 5 → 一致，预置 4+1 空格，进阶源走 M5
