# 研究 06：生存审查——九种死法、砍单清单、开箱体验

> 研究轮次：产品设计 V2 · 2026-09-11 · agent: zxk-F
> 前提：这类系统的真实死法不是做不出来，而是第三周之后没人再打开。

## 一、九种死法（信号 → 预防机制）

**1 维护疲劳（源失效无人修）**
信号：源停更几天，首页仍显示"昨日采集 0 条"而无提示。
预防：源数硬上限 5 个（加源必须先删源，物理限制维护面积）；连续 3 次抓取 0 条 → 首页顶部横幅「2 个源已 3 天无产出 [停用][删除]」，一键处理；抓取失败**不阻断简报**——降级用最近 7 天数据生成，永不空白。

**2 输入枯竭（起步即放弃）**
信号：装完第二天是空页面，配置源 20 分钟还没跑出第一条。
预防：预置源包 + 预置示例机会；首次落地页唯一动作是"粘贴"，不是"配置"。

**3 分析同质化（套话让信任崩塌）**
信号：连续 5 条机会的建议出现同一动词模板；你开始跳过建议只看标题。
预防：① L2 强制输出 `missing_resource`（这条机会必须依赖、而你当前没有的东西），填不出即判定套话重跑；② 红队审查必须引用原文具体数字/主体，否则不通过；③ 禁止无指代动词，建议必须含"今天+一个具体对象+一个可量化成本"；④ **每周盲测**：随机抽 3 条，先自己打 0-100 分再看系统分，落差 >20 分提示「你的口味和系统分歧了」。唯一能对抗漂移的机制。

**4 行动摩擦（收藏夹坟场）**
信号：收藏数上升，但状态推进次数为 0。
预防：**砍掉"收藏"这个零成本动作**，收藏即等于进入「研究中」待办；首页只展示 3 条；每条卡片必须标记"我今天做的一件事"才算消费；「已联系 3 天无动作」自动生成跟进提醒，V1 就要。

**5 价值黑洞（说不清赚了什么）**
信号：跑了 30 天，成交状态为 0，但你还在每天看。
预防：建库第一天强制填「本季度目标」（如"接 1 个 5k 外包"），简报顶部常驻「距目标 0/1，已过 23 天」；每月生成对账单：LLM 花了多少钱 + 你花了多少分钟 vs 产出多少条进入"已联系"。让亏损可见。

**6 过度工程（永远发布不了）**
信号：M1 花了两周还没跑通；你在写周报生成器的时候系统里只有 3 条数据。
预防：时限硬约束——M1 只给一个晚上；周报、webhook、学习权重、多维评分全部锁进"系统连续 7 天有产出"才解锁的开发闸门。

**7 噪音信任崩塌**
信号：简报展示 8 条，你点开 1 条（点击率 <20%）。
预防：把"精度"设为唯一优化指标，允许今日简报只出 1 条；当日合格机会 <3 时首页直接显示「今天没有值得看的机会」，其余折叠进信息库——**宁可空手，绝不凑数**。凑数是信任的头号杀手。

**8 简报变红点（已读不看）**
信号：推送后你不再打开系统，或把推送静音。
预防：推送仅限最高档且含可执行动作，每天最多 1 条；推送文案自带完整行动建议（不打开也能动）；连续 3 天未点击自动降频到每周并告知。V1 先不做推送。

**9 一次数据丢失即永久放弃**
信号：从没演练过恢复流程，data/ 目录不在任何备份里。
预防：每日自动导出 JSON 快照 commit 进私有 git（数据即代码，一次 push 就是备份）。

## 二、砍单审查

| 功能 | 判决 | 理由 |
| --- | --- | --- |
| 每日简报 | **必须有（降级）** | 唯一每日打开理由；砍掉快照固化，首页实时渲染 |
| 周报 | **砍掉** | 日简报都没形成习惯，周报是自嗨产物；等 30 天连续数据 |
| 学习权重 tag_weights | **降级** | 样本 <50 时学出来的权重是随机数；V1 只展示不参与评分 |
| 八维度评分 | **砍到 3 维** | 8 维让 LLM 在弱维度上编数字，且你不会核对 8 个数 |
| 六类机会分类 | **砍到 3 类** | RSS 源几乎不可能可靠识别资源差/价格差，出现即误报 |
| 9 态状态机 | **砍到 4 态** | 新→研究中→已联系→成交/忽略；状态越多滞留越多 |
| 信息源管理后台 | **降级为配置文件 + 只读列表** | 单人改源就是改一个数组，CRUD 界面是做没人用的功能 |
| 手动改分 | **必须有** | 唯一让用户相信"系统不是黑箱"的机制，成本极低（改为改档位） |
| webhook 推送 | **砍掉（V1）** | 你的问题不是"不知道"是"不行动"；附带三重维护 |
| 全文搜索 | **必须有** | 证据库唯一的取用方式；标题+正文即可，不做向量 |
| 去重机制 | **必须有（简化）** | 看到同一条三次你就关页面；只留 url_hash，simhash 留接口 |
| 红队审查 | **必须有，且不可砍** | 本系统和"新闻摘要工具"的唯一区别，防自嗨的唯一机制 |

## 三、只能留一个功能

**保「快速录入 → 5 分钟内得到该不该做 + 第一步做什么」。**

论证：价值 = 收益 × 使用概率。全自动采集收益上限更高，但使用概率被维护成本（源失效、反爬、噪音、成本告警）持续侵蚀——它把"每天打开一次"变成"每天维护一次"，正是第三周死亡的标准路径。"粘贴一条信息"是 30 秒、零维护、永不失效的动作，且价值密度极高：把一条模糊中文需求变成结构化判断（该不该做/第一步/缺什么资源/为什么不成立）——这是自己开个 LLM 对话框做不到的（没有技能画像、没有评分、没有红队）。

关键论证：采集只是**输入放大器**，放大的仍是后面的分析引擎；输入本来就可以是人工的。没有分析引擎，这个产品是 0；没有采集，它只是少一半输入。

## 四、第 1 天开箱体验

**空库时**：不是空列表，而是居中的粘贴框 + 「30 秒，先丢一条进来」+ 下方「看看示例机会」可折叠区。

**预置 3 条示例机会**（标注"示例·可删"，覆盖三种类型与三个分数档 91/78/55）：
① BOSS 上的"某教育公司招 AI 学习工具外包"JD；② "海外某 AI 工具 $29/月、国内无同类"信息差；③ "某 SaaS 涨价 3 倍"价格差。
**目的不是读内容，是校准口味**：每条下面直接问「这机会你会做吗？会/不会」，两次点击立即成为第一批信号，并当场看到"系统的分"和"你的直觉"的分歧。

**预置源包（上限 5 个）**：① Hacker News（Ask/Show HN，官方 API 最稳）② GitHub Trending ③ 1 个中文 RSS（V2EX 或阮一峰周刊，防全英文劝退）④ Product Hunt RSS ⑤ 空 1 格留给用户。
BOSS/闲鱼**不预置为源**，预置成「手动录入」快捷卡片，文案"刷到就粘贴，30 秒"——把合规兜底变成默认动作而非妥协。

**首次 10 分钟路径**：
- 0-1 min：落地只有粘贴框，不配置任何东西
- 1-3 min：粘贴今天真实刷到的一条，显示分析进度（3 秒筛查 / 20 秒深析）
- 3-5 min：出结果——类型 + 分档 + 「该不该做」一句话 + 「今天第一步」+ 红队"为什么不成立"，给「判断对吗？对/不对」两个按钮
- 5-6 min：无论对错都回「已校准」，展示系统理解的技能画像（可编辑）
- 6-8 min：问「要不要加源？」，展示预置源一键启用——**跳过也完全可用**
- 8-10 min：写下本季度目标「我想通过它赚到 ____」——价值黑洞的解药，必须放开箱里
