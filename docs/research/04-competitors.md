# 研究 04：竞品成败研究

> 研究轮次：产品设计 V2 · 2026-09-11 · agent: zfg-D
> 方法：2026-09-11 通过 curl 直接抓取各产品官网验证，非凭印象；无法确认的标注「未验证」。

## 一、四类研究对象现状

### a) 付费趋势简报

| 产品 | 现状（已验证） | 凭什么活 / 为什么死 |
| --- | --- | --- |
| **Trends.vc** | 活。「54,782 founders」「free 5-minute reports」；有 Pro 付费报告、订阅续费条款、NFT 准入实验 | 从纯付费简报 → 免费 5 分钟报告引流 + Pro 深度 + 社区。凭「短报告 + 创始人社区」存活；NFT 准入未验证 |
| **Starter Story** | 活。定位已转向「business ideas backed by real-life case studies」，按营收分级案例库（$3K/mo ~ $500K/mo+），案例付费解锁 | 凭「带营收数据的真实案例库」活。把抽象趋势具象成「别人已经赚到多少钱、怎么赚的」。但本质是回顾性案例，不指向「你今天该做什么」 |
| **The Hustle Trends** | 形态已变。2021 被 HubSpot 收购，原付费产品 Trends 被吸收进 HubSpot 产品营销页 | **付费趋势报告被 SaaS 收购后必然消亡——沦为获客漏斗** |
| **IndieHackers** | 活。被 Stripe 收购。Case Studies DB / Ideas DB / Products DB / IH+ 订阅 | 凭「真实营收数据 + 社区」活。Ideas DB 仍是无差别点子，未匹配个人技能 |

验证机制：①「5 分钟固定时长报告」被 Trends.vc 和 The Hustle 同时采用，是验证过的交付格式；② 用户愿为「真实赚到钱的具体案例」付费，不愿为「泛趋势」付费。

### b) AI 信息聚合（RSS + AI）

| 产品 | 现状 | 留存问题 |
| --- | --- | --- |
| **Feedly** | 活。Leo AI 优先级排序 | 用户不开的真实原因不是「读不过来」，而是「不知道为什么读、读完能干什么」。排序层优化不解决动机层缺失 |
| **Inoreader** | 活。AI 摘要/翻译存在但非主卖点 | 规则过滤、AI 摘要都是 feature-checklist 项，不是留存驱动 |
| **Follow.is** | 活。「noise-free reading with contextual AI」，BYO API key、AI credits、模型可选，开源 | 工程上最进步，但**核心留存问题没被任何 RSS 工具解决：聚合器是「信息管道」，不产生「行动指令」** |

被证伪：①「AI 摘要让信息更好读」≠「用户会回来用」——所有 RSS+AI 工具留存曲线同形：注册→订源→信息堆积→停止打开；②「contextual AI」「noise-free」话术已同质化，不构成差异化。

### c) 国内生意情报

**生财有术**（第十年招新，80000+ 成员）：定位「实战型社区」，关键词「航海」（一群人同一时间做同一个项目，有教练、复盘、同辈压力）。**买单的不是「信息差」，是「项目实战 + 同行者圈子 + 系统课程」三件套**。情报只是入口，留存来自「一起做 + 有人在前面带」。

教训：① 纯「信息差付费专栏」没有项目托底，用户买一次发现「知道≠做到」，第二年不复购（行业共识，未逐一验证）；② 社群人力成本高（教练/航海家），**单人无法复制**。

### d) 商机监测 B 端工具

**企查查/天眼查**：均活。「监控目标企业实时动态」「风险监控」「商业线索」是首页主卖点。**「监控特定实体 → 变更触发推送 → 付费续订」是 B 端最硬的付费闭环之一**；「招投标查询」独立成模块证明「有人正在花钱采购什么」本身可付费。

教训：① 该模型靠「风险规避」驱动，个人机会雷达靠「机会捕获」驱动，动机相反不能直接搬；② 给的是「公司全量信息」而非「机会信号」，信噪比低。

## 二、护城河结论

先排除两个伪护城河：
- **信息覆盖度**：个人单机采集永远输给专业爬虫公司
- **AI 摘要**：Follow 已把「contextual AI/BYO key」做透，AI 周报已泛滥

三个候选判定：
- **领域聚焦**：真空地带（没有产品聚焦「全栈+AI 个人开发者的赚钱机会」persona），但只是切入点，易被复制
- **行动工件**：接近答案。所有竞品都不生成「针对这个机会、匹配你的技能的具体行动物料」——生财有术的「航海」最接近但靠人力社群，单人无法复制
- **个人技能匹配**：真正的护城河底层。所有竞品要么无差别推荐，要么把匹配留给用户自己判断。技能画像作为一等公民、评分核心权重、过滤闸门——是**高门槛但单人可做**的工程问题，做出来体验差异极明显

> **护城河 = 「个人技能画像作为核心过滤器」×「行动工件作为交付单元」**
> Trends.vc 有趋势无匹配，Follow 有摘要无行动，生财有术有项目无个性化，企查查有监控无机会。两者乘积是无人占据的位置，且不依赖社区运营、数据广度、人力教练。

## 三、三条设计推论

1. **技能匹配度是机会排序的第一权重，不是装饰性标签。** 所有竞品的失败源于「无差别推荐」。匹配度应作为**闸门**而非加权项：不达标的机会即使需求再强也只进信息库不进机会中心
2. **每条机会的交付单元是「今天的一个行动」+「行动工件」，不是「一段分析」。** 没有 suggested_action 的机会不允许进入今日简报；简报首条应是「今天最值得行动的一条」+ 具体到联系谁、说什么、报价多少
3. **信息源不求多，求「能产生行动信号」。** 接入标准 =「能否产出 required_skills 和 who_pays 字段」。纯新闻源即使免费也不接。宁可每天 30 条每条有信号，不要 500 条 95% 噪音
