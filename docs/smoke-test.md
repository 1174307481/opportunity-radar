# 冒烟测试包：验证假设 A（AI 分析质量）

> 目的：产品成立与否押在一个假设上——**DeepSeek 能否把真实信息变成「有用不套话」的判断**。
> 时间：10~15 分钟。需要：DeepSeek key（任意聊天界面或 API 均可）。
> 测试材料全部来自 2026-09-11 实抓的真实信息，不是编造样本。

---

## 测试材料（3 条真实信息）

**S1（接单·内容生产）** 电鸭社区 2026-09-09：
> 长期大量需求兼职剪辑师（做东南亚 Tiktok、Facebook 海外内容）

**S2（资源差·收源码）** 电鸭社区 2026-09-10：
> 收完整的闲置项目源码！行业不限类型不限！（1k1条）

**S3（产品空白信号）** Hacker News 2026-09-10：
> Why doesn't a Cursor for Word exist?

---

## 测试一：L1 分类路由（把 3 条一次性给模型）

粘贴以下 prompt（连同 3 条信息）：

```text
你是信息分流器，为「个人商业机会雷达」做初筛。对下面每条信息，输出一行 JSON：
{"id":1,"category":"接单|招聘JD|信息差|价格差|效率差|资源差|产品空白|其他","is_noise":true或false,"has_budget":true或false或null,"required_skills":[{"skill":"技能名","importance":1-5}],"reason":"一句话"}

用户技能画像（判断 required_skills 相关性用）：5年前端（Vue/React/Next/uni-app）+ Java/Spring + Node/NestJS + Python/FastAPI + AI（Agent/RAG/LangGraph/文档解析）+ Docker/K8s + AI内容生产（剪辑/生图/生视频/配音/文案）。

信息列表：
1. [电鸭社区] 长期大量需求兼职剪辑师（做东南亚 Tiktok、Facebook 海外内容）
2. [电鸭社区] 收完整的闲置项目源码！行业不限类型不限！（1k1条）
3. [Hacker News] Why doesn't a Cursor for Word exist?
```

**检查点**：
- [ ] S1 分类为接单/效率差，skills 含剪辑/视频类
- [ ] S2 没被当成噪音（它是有真实价格 ¥1k/条的收购需求），但也没被吹成大机会
- [ ] S3 被识别为「产品空白」信号而非技术提问（Cursor for Word = Word 生态没有 AI 编辑器）
- [ ] 没有编造预算（S1/S2/S3 都没给总价，has_budget 应为 false/null）

## 测试二：L2 行动分析（拿 S1 深析）

粘贴以下 prompt：

```text
你是犀利务实的商业机会分析师，服务对象是下面这位个人开发者。你的建议必须让他今天就能行动，禁止空话。

用户画像：5年前端（Vue/React/Next/uni-app）+ Java/Spring + Node/NestJS + Python/FastAPI + AI（Agent/RAG/LangGraph/文档解析）+ Docker/K8s + AI内容生产（剪辑/生图/生视频/配音/字幕/文案，可用 ffmpeg+AI API 搭批量流水线）。底线时薪 ¥150/小时。

参考打法库（可引用）：
- P06 AI视频/电商素材批量生产：商品图 ¥20-200/张；批量短视频 ¥30-300/条；整包 ¥3k-2万/月；坑：纯AI素材被限流须有实拍料、单价被AI压。
- P05 本地商家AI内容月费：¥2000-8000/月；坑：服务生意不是软件生意，别承诺线索量只承诺条数。

机会原文（来自电鸭社区 2026-09-09）：
「长期大量需求兼职剪辑师（做东南亚Tiktok、Facebook海外内容）」

请输出 JSON，包含：
1. evidence_trilogy 真伪三证：资金证据/身份证据/时间证据，各给原文依据或 null，结论（可推进/降级观察）
2. scores 四维打分（0-100，每维 reason 必须引用原文具体字词）：需求真实性40、行动可行性30、独特性15、时效性15
3. skill_match：需求技能+重要度1-5，对照画像逐项命中情况 + 匹配度总分
4. devil_advocate 红队审查：论证这个机会为什么不成立（必须基于原文与常识，例如单价、量、渠道真实性等具体风险）
5. hourly_check 时薪反算：预估单价÷预估工时 vs 底线时薪，数字拿不准写 null 并说明
6. verdict 该不该做：一句话
7. first_step 第一步（今天）：时间盒+动作动词+对象+渠道+数量+完成判定（只定义用户可控的行为：发出即完成）+ 可直接复制发送的第一句话术（≤80字，不得有群发腔）

注意：预算类数字原文没有的必须输出 null，禁止编造。
```

**检查点（10 项）**：
- [ ] 1. 三证如实标注缺失（没编造预算）
- [ ] 2. 四维每维理由都引用了原文（「长期大量」「海外内容」等字眼）
- [ ] 3. 红队点出真实风险：剪辑红海/单价被压/对方身份不明/海外内容合规，而不是泛泛「竞争激烈」
- [ ] 4. 区分了「单条剪辑接单」vs「批量流水线」——正确打法接近 P06 而非降权词表里的裸剪辑
- [ ] 5. 时薪反算有具体数字或诚实写 null
- [ ] 6. 匹配度合理（该用户剪辑/文案/自动化全命中，应 ≥80；不会为了讨好给 100）
- [ ] 7. 第一步有时间盒 + 对象 + 渠道
- [ ] 8. 完成判定是用户可控行为（发出即完成，不是「等对方回复」）
- [ ] 9. 话术可直接复制发送，像人话不像群发
- [ ] 10. **总判定：你愿不愿意照着第一步真的发这条私信？**（核心一条）

## 判定

| 结果 | 行动 |
| --- | --- |
| ≥8/10 通过 | 假设 A 成立 → 当晚开 M1 |
| 5~7 通过 | 架构成立，prompt 要调 → 失败项贴回来，调完再跑一次（仍是 M1 范围内的活） |
| <5 通过 | 把完整输出贴回来，逐项诊断是模型能力问题还是 prompt 问题 |

测试完把两次输出贴回来，据此定稿 M1 的正式 prompt。

# 测试结果（2026-09-11 实跑，deepseek-v4-flash @ 现有网关）

## Test1 L1 路由：3/4 通过

- ✅ S1 → 接单，skills 抽取含「视频剪辑(5)/短视频内容生产(4)/AI生图生视频(3)」
- ✅ S2 → 资源差，is_noise=false，¥1k/条 被正确捕获为价格信号
- ✅ S3 → 产品空白（识别出「Word 版 Cursor」= 文档 AI 编辑器空白），skills 抽出 LLM应用落地/文档解析
- ❌ S1 `has_budget:true` 是误报——原文没有任何价格，规则必须改成「原文出现明确数字才算 true」

## Test2 L2 行动分析：9/10 通过

1. ✅ 三证全部如实标 null（没编造预算），总评「降级观察：可发1条零成本验证，不先试剪」
2. ✅ 四维理由全部引用原文（「长期大量需求兼职剪辑师」「2026-09-09」）
3. ✅ 红队 5 条全是具体风险：无单价可能是低价走量/收简历、红海压价守不住 ¥150 时薪、缺东南亚本地化能力（画像盲区，人没发现模型发现了）、中介/二道贩子风险、试稿不付费风险——并引用了 P06 的坑（纯AI素材被限流须实拍料）
4. ✅ 区分了裸剪辑（降权）vs 批量流水线（P06）
5. ✅ 时薪反算诚实输出 null：「任何反算都是编造。先问四项：单条时长/¥条、月量、素材谁给、结算规则」
6. ⚠️ 匹配度 72（预期 ≥80）——但原因是模型诚实扣掉了「东南亚本地化未命中」，属于合理偏差，比讨好式 95 分更有价值
7. ✅ 第一步含时间盒（今天15分钟内）+ 对象（发帖人）+ 渠道（电鸭原帖私信）
8. ✅ 完成判定=「消息成功发出即完成，不等回复、不承诺试剪」
9. ✅ 话术直接可用：「看到你招东南亚TikTok/Facebook兼职剪辑。我接批量短视频，能问下：单条时长、结算单价、日/月量、素材由谁给？合适我先试剪1条。」
10. ⚠️ 话术末尾「合适我先试剪1条」与 verdict「不先试剪」轻微不一致（可解释为拿到报价后的有偿试剪，但正式 prompt 要把试剪边界写死）

## 总判定：**假设 A 成立（≈8.5/10）→ 开 M1**

## M1 必须带走的 4 条工程结论

1. **该网关的 deepseek-v4-flash 是思考型模型**：返回含 `thinking` 内容块且思考 token 计入 `max_tokens`——L1 要 ≥6000、L2 要 ≥12000，文本提取只取 `type=="text"` 块（Vercel AI SDK 会自动处理）
2. 接入协议：Anthropic 兼容 `/v1/messages` + `x-api-key`（网关 `ANTHROPIC_BASE_URL`，模型名 `deepseek-v4-flash`，不izarre 需要 vision-exp-direct 后缀）
3. L1 规则修订：`has_budget` 只在原文出现明确数字时为 true；L2 prompt 增加「试剪/试稿必须写明有偿或免费边界」
4. 成本实测：单条完整 L1+L2 分析 ≈ 6.4k 输出 tokens（含思考），按 flash 档价格可忽略；100 条/天远低于预算线

## M1 端到端实测（2026-09-11 晚，生产构建 + 真实数据）

**链路**：POST /api/items → L1（6000tok）→ L2（12000tok）→ 评分/分档 → dashboard/详情页，全通。三页 HTTP 200。

| 样本 | L1 判定 | match | score | tier | 复核 |
| --- | --- | --- | --- | --- | --- |
| 电鸭：东南亚 TikTok 剪辑兼职，80-150 元/条 | 接单，has_budget=true（80-150元/条） | 43 | 15 | 🔴 today（⚡快通道） | ✅ 符合设计：L2 给低分（TG 中介身份弱）但快通道进今天看，第一步=验证结算/验收/拒免费试稿 |
| HN：Cursor for Word（医疗病历 AI add-in） | 产品空白 | 18（修复后） | 16 | ⚪ archived | ✅ 诚实：LLM 子技能命中但 HIPAA/离线/Add-in 主体不匹配，宁空勿凑；信息库可手动改档捞回 |

**实测发现并已修复的 3 条规则**（M1 定稿）：

1. **技能匹配三级兜底**：精确→别名→拆 token（`/、，,&`）→去括号→子串包含（别名≥2字、canonical≥3字，覆盖 llm/rag/k8s）。修复前「AI工具提效（剪映/功能型AI剪辑）」「LLM 结构化病历生成」均 miss。
2. **软技能出分母**：网感/沟通/审美等进 SOFT_SKILLS 集合，不参与匹配（修复前稀释分母，43→29 的元凶之一）。
3. **快通道门槛改为 coreHit**：`接单+明确预算+importance≥4 的硬技能至少一条命中` → 🔴，取代 `skillMatch≥60` 且优先级高于 `match<40 归档`。理由：快通道的价值在「用第一步验证代替分数门槛」，被 60 分门槛卡死等于快通道不存在。

**工程数据**：L2 稳定输出 ~7100 output tokens（上限 12000 合理）；L1 ~1100；单条全链路 ~55-70s；URL 抓取失败（如 HN 被墙）时报错并引导改粘贴文本——M3 按源配代理。

**遗留（非阻塞）**：改档/状态的行为账已入库（user_actions），M2 做搜索+4态机时一起消化。
